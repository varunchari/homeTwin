## Goal

Ship a judging-aligned HomeTwin MVP by Nov 4, 9 PM ET: turn one room photo into selectable regions, bind them to real Home Assistant entities, and let users tap-to-control plus draw/text-to-automate through a safe, approval-gated pipeline, with a 3-minute video and public submission.

## Success Criteria

- P0 works end to end by Oct 31 and stays frozen: HA Core control plane, photo → SAM 3.1 masks + manual fallback → scene graph, manual binding, tap-to-control, Muse Spark → AutomationIR → deterministic compiler → approval → deploy → observe HA state, for all 3 automation patterns, plus basic What-If preview and one-click reset.
- Stage 1 passes: project fits Build for Your World or Push the Frontier and shows real Meta Model API / open-weight usage (no mock passed off as real).
- Stage 2 evidence exists: Impact (room beats device list), Meta Tooling (SAM + Spark + optional Image/Voice), Technical Depth (real HA execution, allowlist, traces, reset), Demo (uninterrupted 3-minute walkthrough with visible state changes + reliable public URL).
- Submission is complete: public repo with Oct 27–Nov 4 project commits, accessible live product, 3-minute video, track + contributors + license + image attribution, no secrets or personal telemetry in repo/video.

## Approach

Build P0 first, one room, minimal devices, one compiler. Add at most two P1s only after P0 passes, in fixed order. Cut ruthlessly per the cut ladder.

- One authoritative control plane: HA Core owns device states and automations; HomeTwin owns images, masks, spatial IDs, bindings, interaction; a backend proxy mediates all HA calls; HA credentials stay server-side; frontend state comes only from HA WebSocket `state_changed` (no optimistic UI).
- One compiler, three templates: (1) state → action, e.g. door opens → light ON; (2) state + condition → action, e.g. door opens after sunset → light ON; (3) state → action + delay, e.g. motion ON → lamp ON, OFF after delay (1-minute variant for live testing; 15-minute rule for demo record). Live demo rule has NO sunset condition; sunset lives in What-If/preview only.
- Safety allowlist, no exceptions: door trigger, `light.turn_on` / `light.turn_off`, sun condition only. No locks, alarms, garage doors, heaters, covers, arbitrary YAML. No LLM-generated YAML executed. Every HA write needs in-UI user approval; every rejection carries a plain-language reason.
- Locked decisions carried from Oct 26 (do not relitigate): Standard `muse-spark-1.3` for everything (verify with `/models` each session; resume with `muse resume --last`, check `git status`/`git diff` for in-flight work; `/stop` background tasks + push before closing); $150 Meta credits confirmed + payment method + spend notifications; $100 Baseten credit is a gated Oct-30 AutomationIR A/B experiment only (model id `meta-models/muse-spark-open`, verify any dated label against the Baseten dashboard before hard-coding; OpenAI-compatible `https://inference.baseten.co/v1`, `BASETEN_API_KEY` server-side only; NOT for SAM/image/transcription/Muse Code/GPU); Modal/Fireworks remain fallback insurance only, never core; Muse Code interactive CLI, approve every diff, no `--yolo`, no unofficial GUI; two Standard keys (backend + Muse Code), never in repo/browser/screenshots; Indie track default unless HomeTwin is a venture (confirm Day 1, one track only).
- Hosting locked (v1.6): Lightsail $24/mo 4 GB / 2 vCPU / 80 GB, Ubuntu 24.04 LTS (OS only), Oregon (us-west-2), static IP attached, firewall 80/443 (+ SSH from your IP only), paid from $100 AWS signup credit with $10 budget alert. Instance created + SSH-verified Oct 26 — Day 1 verifies, does NOT recreate. HA container has no published port (backend proxy only, over Docker network, token in `.env` only); Caddy is the only thing on 80/443. Keep through finals Nov 9, then delete instance AND release static IP.
- GitHub: remote `origin` already points at the user's repo — confirm it exists, do NOT create a second repo. Push needs SSH key or PAT (classic, `repo` scope); initial/project commits use the user's git identity.
- Evidence and provenance: log every model call (model name, request, latency, output, validation status, cost); commit daily with dated messages; README states "Built during hackathon" with track, contributors, license, image attribution; demo-room image is generated (rights-clean, freeze Oct 28, record source as generated, never re-shoot mid-sprint).

## Validation Plan

- Steps 1–5: each day's exit test in Steps is the definition of done (do not accept "Muse Code says it works"). Highest-risk gate: Step 5 P0 loop repeated 3x + What-If both paths + reset — if flaky, stop P1 and harden.
- Models: evidence log per call; spot-check that every submitted beat shows a real completed call, fallbacks labelled; Stage 1 viability fails on mocks.
- Safety: attempt disallowed automation (lock/cover/arbitrary action/unknown entity) → must reject with plain-language reason; confirm approval screen precedes every HA write; confirm HA creds absent from browser/repo.
- Release: fresh-browser no-prior-session full loop; video plays ≤3:00 with legible state changes; public repo + live link + video link all accessible; secret scan clean; README switched to shipped-only present tense.
